# E62 Dashboard 使用與維運手冊

## 1. 部署與資料位置

客戶端不需安裝 Node.js、Angular 或 SQLite，直接執行：

```text
E62-Angular-Dashboard-Demo-1.0.0-Windows-x64.exe
```

Portable EXE 可搬動，但資料庫保存在：

```text
%APPDATA%\angular-dashboard\data\e62-dashboard.sqlite3
```

## 2. 初次設定

1. 以展示管理員登入。
2. 在「設定」選擇 Mock 或 Live。
3. Live 模式填入 API URL、Token 與輪詢間隔。
4. 設定歷史資料保留天數。
5. 建立客戶正式管理帳號並更換所有預設密碼。
6. 確認儀錶板、報表查詢及 CSV 匯出正常。

## 3. 日常檢查

- 最新資料時間持續更新，Alarm／Error 與現場一致。
- 報表能查到最近資料，匯出筆數合理。
- data 所在磁碟有足夠空間。
- 定期完整備份 data 資料夾並抽測還原。

## 4. 備份與還原

最安全方式是關閉程式，確認程序結束，再複製整個 `data` 資料夾。WAL 模式可能有 `.sqlite3-wal` 和 `.sqlite3-shm`，不可只複製主檔。

還原前關閉程式並先另存目前資料，再以完整備份取代 data 資料夾。啟動後驗證登入、設定、最新資料、報表及匯出。

## 5. 故障排除

### 沒有即時資料

- 檢查 `data.mode`。
- Live 模式檢查 URL、Token、網路、防火牆及回應是否含非空 `channels`。
- 確認登入角色有 `dashboard.view`。

### 能查報表但不能匯出

- 使用者需有 `reports.export`；Guest 預設不能匯出。
- 確認目的資料夾可寫，CSV 沒被 Excel 鎖定。

### 無法登入

- 帳號不分大小寫，密碼有大小寫差異，並檢查帳號是否停用。
- 遺失所有管理員密碼時，先完整備份再由維護人員受控重設；不要刪除資料庫。

### 資料庫快速變大

每日筆數約為 `通道數 × 86,400,000 ÷ 輪詢毫秒`。200 通道每 3 秒會產生 5,760,000 筆／日。應縮短保留期、降低報表落庫頻率、改為變動／彙總寫入，或採伺服器型資料庫。

### 懷疑資料庫損壞

1. 關閉程式並複製整個 data 資料夾。
2. 不要直接刪除 WAL、SHM 或主資料庫。
3. 由維護人員在副本執行 `PRAGMA integrity_check`。
4. 優先還原最近一次已驗證的完整備份。

## 6. 更新版本

第一版尚無正式 schema migration。升級前必須完整備份，先在副本驗證新版可讀取舊設定與歷史資料，並確認登入、查詢及匯出正常。

## 7. 交付檢查清單

- EXE 可在乾淨 Windows x64 電腦啟動。
- API URL、Token、輪詢與保留期已確認。
- 客戶已建立正式管理員並更換預設密碼。
- 角色菜單、查詢及匯出權限符合需求。
- API 資料能完整寫入，重啟後仍可查詢。
- CSV 可由 Excel 正確顯示中文。
- 備份位置、週期、保留代數與還原負責人已確認。
- 已依實際通道數與頻率完成容量估算。
